# UO.Luck

ClassicUO • Runtime API

<!-- yoko-manual: 1 -->
<!-- yoko-locale: uk -->

Читає лічильник статусу власного персонажа: очки удачі.

## Точний синтаксис

```text
UO.Luck() -> Integer
```

## Параметри

Параметрів немає.

## Повертає

Integer — очки удачі, 0..65535 у моделі клієнта. 0 може бути фактичним значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1 означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

## Поведінка

- Команда не приймає аргументів. Використовуйте точні сигнатури вище.
- Читання в ігровому потоці бере Player.Luck, якщо поточний Player існує й не знищений; інакше 0. Спорядження не перебирається, бонуси не перераховуються, статус не запитується, очікування оновлення немає. Наявний привид не є знищеним Player.
- Luck читає серверні очки удачі, збережені як UInt16, зі статусу type >= 4. Це не відсоток, випадкове число чи гарантія якості здобичі. Читання не обчислює ймовірність випадіння й не додає бонуси спорядження.
- CharacterStatus перевіряє обов’язкове тіло перед оновленням. Weight є у власному розширеному статусі, слоти — з type 3, Luck — з type 4, серверний WeightMax — з type 5. Компактний/старий пакет без необов’язкового лічильника лишає попередній кеш. Новий Player починає з нулів; виклик не доводить свіжість статусу.
- RegisterCharacterGetterAliases додає відсутні функції без аргументів і вбудовані імена для поля. Наявні гілки сумісності читають те саме поле bridge. Регістр не важливий; intrinsic без дужок читається заново, якщо його не перекрила змінна.
- Кожен виклик читає локальні дані заново. Змінна зберігає знімок; окремі читання можуть бачити різні оновлення сервера. Ненульовий результат не перевіряє з’єднання. Нуль буває значенням або відсутністю даних.

### Внутрішні функції: від виклику до результату

Внутрішні етапи читання кешованого лічильника. Повністю оголошена CanCarry, LuckAtLeast чи CanAddFollower у прикладі — користувацький BASIC, не прихована нативна дія. Вона не змінює інвентар чи улюбленців.

#### 1. RegisterCharacterGetterAliases

RegisterCharacterGetterAliases додає відсутні функції без аргументів і вбудовані імена для поля. Наявні гілки сумісності читають те саме поле bridge. Регістр не важливий; intrinsic без дужок читається заново, якщо його не перекрила змінна.

`Luck GetLuck`.

Код проєкту: `external/InjectionScript/src/InjectionScript/Runtime/InjectionApiUO.cs`; функція `RegisterCharacterGetterAliases`.

#### 2. Invoke

Читання в ігровому потоці бере Player.Luck, якщо поточний Player існує й не знищений; інакше 0. Спорядження не перебирається, бонуси не перераховуються, статус не запитується, очікування оновлення немає. Наявний привид не є знищеним Player.

Invoke читає на ігровому потоці; очікування можна скасувати разом зі скриптом. Не запитує status, не відкриває target, не надсилає пакета, не змінює характеристику й не додає затримки.

Код проєкту: `src/ClassicUO.Client/Game/Managers/ClassicUOInjectionApiBridge.cs`; функція `Invoke`.

#### 3. CharacterStatus

CharacterStatus перевіряє обов’язкове тіло перед оновленням. Weight є у власному розширеному статусі, слоти — з type 3, Luck — з type 4, серверний WeightMax — з type 5. Компактний/старий пакет без необов’язкового лічильника лишає попередній кеш. Новий Player починає з нулів; виклик не доводить свіжість статусу.

Luck читає серверні очки удачі, збережені як UInt16, зі статусу type >= 4. Це не відсоток, випадкове число чи гарантія якості здобичі. Читання не обчислює ймовірність випадіння й не додає бонуси спорядження.

Код проєкту: `src/ClassicUO.Client/Network/PacketHandlers.cs`; функція `CharacterStatus`.

#### 4. Clear

World.Clear прибирає Player. Далі повертається 0, доки не з’являться поточний персонаж і його дані. Збережене значення не доводить виконання вимоги після перепідключення.

Integer — очки удачі, 0..65535 у моделі клієнта. 0 може бути фактичним значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1 означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

Код проєкту: `src/ClassicUO.Client/Game/World.cs`; функція `Clear`.

### Повна допоміжна функція

```vb
# Повна допоміжна функція
#
# Читає лічильник статусу власного персонажа: очки удачі.
#
# Integer — очки удачі, 0..65535 у моделі клієнта. 0 може бути фактичним значенням, браком даних
# або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1 означає одну одиницю,
# не успіх. Виклик не перебирає об’єкти й не повертає масив.

SUB Main()
    # LuckAtLeast(minimum) отримує числову вимогу; 1000 — приклад, не межа чи відсоток. Відхиляє
    # відсутній Player, читає удачу один раз і повертає Integer Boolean: 1=TRUE чи 0=FALSE за value
    # >= minimum. Сама удача не Boolean. Порівнюються кешовані очки, здобич не передбачається.

    IF LuckAtLeast(1000) = TRUE THEN
        UO.Print('Local check passed')
    ELSE
        UO.Print('Local check failed or data unavailable')
    END IF
END SUB

SUB LuckAtLeast(minimum)
    IF UO.Self() = 0 THEN
        RETURN FALSE
    END IF
    VAR value = UO.Luck()
    RETURN value >= minimum
END SUB
```

**Пояснення параметрів і виконання:**

- LuckAtLeast(minimum) отримує числову вимогу; 1000 — приклад, не межа чи відсоток. Відхиляє відсутній Player, читає удачу один раз і повертає Integer Boolean: 1=TRUE чи 0=FALSE за value >= minimum. Сама удача не Boolean. Порівнюються кешовані очки, здобич не передбачається.
