# UO.GetResist

ClassicUO • Runtime API

<!-- yoko-manual: 1 -->
<!-- yoko-locale: uk -->

Читає один опір власного персонажа за числовим або рядковим селектором.

## Точний синтаксис

```text
UO.GetResist(resistance:Any) -> Integer
```

## Параметри

- `resistance` — resistance обов’язковий. Числа: 0=physical, 1=fire, 2=cold, 3=poison, 4=energy. Рядки: physical/phys/armor, fire, cold, poison, energy. Регістр і крайні пробіли ігноруються. Немає serial, type, hue, прицілу чи другого аргументу.

## Повертає

Integer — знакове значення статусу, -32768..32767 у моделі клієнта. Від’ємне значення зберігається. 0 може бути фактичним опором, відсутнім полем або відсутнім/знищеним Player; GetResist також дає 0 для невідомого селектора. Це не Boolean, ID, навичка чи межа опору. 1 означає один пункт, а не успішне виконання.

## Поведінка

- GetResistance спершу розрізняє тип: рядки "1" та "0" — невідомі назви, дають 0 і не є числовими селекторами. Нерядковий Decimal відкидає дріб до нуля: 1.9 -> fire, -0.9 -> physical. TRUE=1 обирає fire, FALSE=0 — physical; Array/Unit також перетворюються на 0. Використовуйте явне ціле чи допустиму назву. Імена AddObject не розпізнаються.
- GetResistance обирає рівно одне поле bridge. Невідомі числа/назви дають Integer 0 без читання поля. Виклик не знімає п’ять значень атомарно й не змінює опори.
- PhysicalResistance — серверне поле броні/статусу: класичний сервер може передавати рейтинг броні, а правила з опорами — фізичний опір. API не перетворює одне на інше й не обчислює відсоток зменшення шкоди. Armor і фізичні псевдоніми читають те саме поле.
- Стихійні поля надходять у розширеному CharacterStatus (0x11), type >= 4. Сам виклик не перевіряє еру сервера. Компактний/старий статус без цих полів лишає попередній кеш; новий Player починає з 0. Опір отруті не є прапорцем Poisoned; це також не навичка Resisting Spells.
- CharacterStatus перевіряє обов’язкове тіло до зміни імені, здоров’я та власних характеристик, потім перетворює кожне слово опору на знаковий Int16. Обрізане обов’язкове тіло не змінює попередні дані. Необов’язковий хвіст type 6 зберігає свої правила; ці команди не читають із нього максимальні межі.
- Invoke читає на ігровому потоці; очікування можна скасувати разом зі скриптом. Не запитує status, не відкриває target, не надсилає пакета, не змінює характеристику й не додає затримки.
- Кожен виклик читає локальні дані заново. Змінна зберігає знімок; окремі читання можуть бачити різні оновлення сервера. Ненульовий результат не перевіряє з’єднання. Нуль буває значенням або відсутністю даних.

### Внутрішні функції: від виклику до результату

Фактичні внутрішні етапи локального читання опору. ResistanceAtLeast нижче — повністю оголошена користувацька BASIC-функція, а не прихований API чи надягання захисного спорядження.

Реєструє GetResist(resistance) та UO.GetResist(resistance) як функції з одним аргументом, пов’язані з GetResistance. Вбудованого імені без аргументу для цього селектора немає.

#### 3. ToInt

ToInt тут отримує лише нерядковий селектор. Integer зберігається, Decimal відкидає дріб до нуля, Array/Unit дають 0. Результат — індекс селектора, не опір. Рядкові назви розбирає GetResistance.

`0: PhysicalResistance; 1: FireResistance; 2: ColdResistance; 3: PoisonResistance; 4: EnergyResistance`.

Код проєкту: `external/InjectionScript/src/InjectionScript/Runtime/NumberConversions.cs`; функція `ToInt`.

#### 4. Invoke

Invoke читає вибране поле Player із таблиці вище, зберігаючи знак. Немає/знищено Player — 0. Читання не запитує статус і не чекає нових даних.

Invoke читає на ігровому потоці; очікування можна скасувати разом зі скриптом. Не запитує status, не відкриває target, не надсилає пакета, не змінює характеристику й не додає затримки.

Код проєкту: `src/ClassicUO.Client/Game/Managers/ClassicUOInjectionApiBridge.cs`; функція `Invoke`.

## Приклади

### Обрати назву з різним регістром

```vb
# Обрати назву з різним регістром
#
# Читає один опір власного персонажа за числовим або рядковим селектором.
#
# Integer — знакове значення статусу, -32768..32767 у моделі клієнта. Від’ємне значення
# зберігається. 0 може бути фактичним опором, відсутнім полем або відсутнім/знищеним Player;
# GetResist також дає 0 для невідомого селектора. Це не Boolean, ID, навичка чи межа опору. 1
# означає один пункт, а не успішне виконання.

SUB Main()
    # resistance=" FiRe " обирає вогонь без крайніх пробілів і без урахування регістру. value
    # лишається знаковим числом; приціл не з’являється.

    VAR value = UO.GetResist(' FiRe ')
    UO.Print('Fire resistance: ' + CStr(value))
END SUB
```

**Пояснення параметрів і виконання:**

- resistance=" FiRe " обирає вогонь без крайніх пробілів і без урахування регістру. value лишається знаковим числом; приціл не з’являється.

### Порівняти числовий і рядковий селектори

```vb
# Порівняти числовий і рядковий селектори
#
# Читає один опір власного персонажа за числовим або рядковим селектором.
#
# Integer — знакове значення статусу, -32768..32767 у моделі клієнта. Від’ємне значення
# зберігається. 0 може бути фактичним опором, відсутнім полем або відсутнім/знищеним Player;
# GetResist також дає 0 для невідомого селектора. Це не Boolean, ID, навичка чи межа опору. 1
# означає один пункт, а не успішне виконання.

SUB Main()
    # 2 обирає холод; "poison" — отруту. Це селектори, не serial. Порівняння двох знімків повертає
    # Boolean; опір отруті не вказує, чи отруєний персонаж.

    VAR cold = UO.GetResist(2)
    VAR poison = UO.GetResist('poison')
    IF cold < poison THEN
        UO.Print('Cold resistance is lower')
    ELSE
        UO.Print('Cold resistance is equal or higher')
    END IF
END SUB
```

**Пояснення параметрів і виконання:**

- 2 обирає холод; "poison" — отруту. Це селектори, не serial. Порівняння двох знімків повертає Boolean; опір отруті не вказує, чи отруєний персонаж.

### Повна функція перевірки мінімального опору

```vb
# Повна функція перевірки мінімального опору
#
# Читає один опір власного персонажа за числовим або рядковим селектором.
#
# Integer — знакове значення статусу, -32768..32767 у моделі клієнта. Від’ємне значення
# зберігається. 0 може бути фактичним опором, відсутнім полем або відсутнім/знищеним Player;
# GetResist також дає 0 для невідомого селектора. Це не Boolean, ID, навичка чи межа опору. 1
# означає один пункт, а не успішне виконання.

SUB Main()
    # minimum=50 — приклад вимоги, не межа клієнта. ResistanceAtLeast відхиляє відсутнього Player,
    # читає одне значення й повертає Integer Boolean: 1=TRUE чи 0=FALSE за value >= minimum. Сам
    # опір не Boolean. Функцію повністю оголошено нижче.
    # selector передається з функції в GetResist без змін; приклад використовує "fire". Функція
    # перевіряє наявність Player, але не довільний селектор і не свіжість статусу. Використовуйте
    # селектор зі списку вище.

    IF ResistanceAtLeast('fire', 50) = TRUE THEN
        UO.Print('Local fire resistance requirement met')
    ELSE
        UO.Print('Requirement not met or no player')
    END IF
END SUB

SUB ResistanceAtLeast(selector, minimum)
    IF UO.Self() = 0 THEN
        RETURN FALSE
    END IF
    VAR value = UO.GetResist(selector)
    RETURN value >= minimum
END SUB
```

**Пояснення параметрів і виконання:**

- minimum=50 — приклад вимоги, не межа клієнта. ResistanceAtLeast відхиляє відсутнього Player, читає одне значення й повертає Integer Boolean: 1=TRUE чи 0=FALSE за value >= minimum. Сам опір не Boolean. Функцію повністю оголошено нижче.
- selector передається з функції в GetResist без змін; приклад використовує "fire". Функція перевіряє наявність Player, але не довільний селектор і не свіжість статусу. Використовуйте селектор зі списку вище.
