# UO.GetFollowers

ClassicUO • Runtime API

<!-- yoko-manual: 1 -->
<!-- yoko-locale: uk -->

Читає лічильник статусу власного персонажа: зайняті слоти керування улюбленцями.

## Точний синтаксис

```text
UO.GetFollowers() -> Integer
```

## Параметри

Параметрів немає.

## Повертає

Integer — зайняті слоти керування улюбленцями, 0..255 у моделі клієнта. 0 може бути фактичним значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1 означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

## Поведінка

- Команда не приймає аргументів. Використовуйте точні сигнатури вище.
- Читання в ігровому потоці бере Player.Followers, якщо поточний Player існує й не знищений; інакше 0. Спорядження не перебирається, бонуси не перераховуються, статус не запитується, очікування оновлення немає. Наявний привид не є знищеним Player.
- PetsCurrent/Followers повідомляє зайняті слоти керування з власного статусу type >= 3. Один улюбленець може займати кілька слотів; правила для викликаних і приручених істот задає сервер. Це не кількість видимих mobile, не список ID улюбленців і не число тварин поруч.
- CharacterStatus перевіряє обов’язкове тіло перед оновленням. Weight є у власному розширеному статусі, слоти — з type 3, Luck — з type 4, серверний WeightMax — з type 5. Компактний/старий пакет без необов’язкового лічильника лишає попередній кеш. Новий Player починає з нулів; виклик не доводить свіжість статусу.
- RegisterCharacterGetterAliases додає відсутні функції без аргументів і вбудовані імена для поля. Наявні гілки сумісності читають те саме поле bridge. Регістр не важливий; intrinsic без дужок читається заново, якщо його не перекрила змінна.
- Кожен виклик читає локальні дані заново. Змінна зберігає знімок; окремі читання можуть бачити різні оновлення сервера. Ненульовий результат не перевіряє з’єднання. Нуль буває значенням або відсутністю даних.

### Повна допоміжна функція

```vb
# Повна допоміжна функція
#
# Читає лічильник статусу власного персонажа: зайняті слоти керування улюбленцями.
#
# Integer — зайняті слоти керування улюбленцями, 0..255 у моделі клієнта. 0 може бути фактичним
# значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1
# означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

SUB Main()
    # CanAddFollower(extraSlots) отримує потрібні слоти; 2 — приклад для однієї істоти з двома
    # слотами, не обов’язково двох істот. Відхиляє від’ємне число, відсутній Player або maximum <=
    # 0, читає зайняті слоти/межу й повертає Integer Boolean: 1=TRUE чи 0=FALSE за extraSlots <=
    # maximum - current. Немає переповнення додавання; перевищення межі дає false навіть для нуля.
    # Не перевіряє власника, навичку приручення чи дозвіл сервера. Між читаннями можливі оновлення.

    IF CanAddFollower(2) = TRUE THEN
        UO.Print('Local check passed')
    ELSE
        UO.Print('Local check failed or data unavailable')
    END IF
END SUB

SUB CanAddFollower(extraSlots)
    IF extraSlots < 0 OR UO.Self() = 0 THEN
        RETURN FALSE
    END IF
    VAR current = UO.GetFollowers()
    VAR maximum = UO.PetsMax()
    IF maximum <= 0 THEN
        RETURN FALSE
    END IF
    RETURN extraSlots <= maximum - current
END SUB
```

**Пояснення параметрів і виконання:**

- CanAddFollower(extraSlots) отримує потрібні слоти; 2 — приклад для однієї істоти з двома слотами, не обов’язково двох істот. Відхиляє від’ємне число, відсутній Player або maximum <= 0, читає зайняті слоти/межу й повертає Integer Boolean: 1=TRUE чи 0=FALSE за extraSlots <= maximum - current. Немає переповнення додавання; перевищення межі дає false навіть для нуля. Не перевіряє власника, навичку приручення чи дозвіл сервера. Між читаннями можливі оновлення.
