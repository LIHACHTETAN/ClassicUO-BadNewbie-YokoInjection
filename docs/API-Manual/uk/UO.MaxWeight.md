# UO.MaxWeight

ClassicUO • Runtime API

<!-- yoko-manual: 1 -->
<!-- yoko-locale: uk -->

Читає лічильник статусу власного персонажа: максимальна вага у stones.

## Точний синтаксис

```text
UO.MaxWeight() -> Integer
```

## Параметри

Параметрів немає.

## Повертає

Integer — максимальна вага у stones, 0..65535 у моделі клієнта. 0 може бути фактичним значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1 означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

## Поведінка

- Команда не приймає аргументів. Використовуйте точні сигнатури вище.
- Читання в ігровому потоці бере Player.WeightMax, якщо поточний Player існує й не знищений; інакше 0. Спорядження не перебирається, бонуси не перераховуються, статус не запитується, очікування оновлення немає. Наявний привид не є знищеним Player.
- MaxWeight читає кеш WeightMax. Власний статус type >= 5 задає серверну межу UInt16, навіть 0. Старий розширений статус обчислює її один раз під час отримання: протокол UO >= 5.0.0a — 7 * floor(STR / 2) + 40; старіший — STR * 4 + 25. Результат зберігається як UInt16, крайні значення обертаються за модулем 65536. STR=101 дає відповідно 390 або 429. Сам getter не перераховує межу після окремої зміни STR.
- CharacterStatus перевіряє обов’язкове тіло перед оновленням. Weight є у власному розширеному статусі, слоти — з type 3, Luck — з type 4, серверний WeightMax — з type 5. Компактний/старий пакет без необов’язкового лічильника лишає попередній кеш. Новий Player починає з нулів; виклик не доводить свіжість статусу.
- RegisterCharacterGetterAliases додає відсутні функції без аргументів і вбудовані імена для поля. Наявні гілки сумісності читають те саме поле bridge. Регістр не важливий; intrinsic без дужок читається заново, якщо його не перекрила змінна.
- Кожен виклик читає локальні дані заново. Змінна зберігає знімок; окремі читання можуть бачити різні оновлення сервера. Ненульовий результат не перевіряє з’єднання. Нуль буває значенням або відсутністю даних.

### Повна допоміжна функція

```vb
# Повна допоміжна функція
#
# Читає лічильник статусу власного персонажа: максимальна вага у stones.
#
# Integer — максимальна вага у stones, 0..65535 у моделі клієнта. 0 може бути фактичним
# значенням, браком даних або відсутнім/знищеним Player. Це кількість, не Boolean, ID чи type: 1
# означає одну одиницю, не успіх. Виклик не перебирає об’єкти й не повертає масив.

SUB Main()
    # CanCarry(extra) отримує додаткову вагу у stones; 10 — приклад, не число стосів. Відхиляє
    # від’ємний extra, відсутній Player або maximum <= 0, читає вагу й межу та повертає Integer
    # Boolean: 1=TRUE чи 0=FALSE за extra <= maximum - current. Віднімання уникає переповнення
    # current + extra. Перевантаження дає false навіть для extra=0. Це локальна оцінка, не дозвіл
    # сервера; читання не атомарні, нульова вага може бути невідомою.

    IF CanCarry(10) = TRUE THEN
        UO.Print('Local check passed')
    ELSE
        UO.Print('Local check failed or data unavailable')
    END IF
END SUB

SUB CanCarry(extra)
    IF extra < 0 OR UO.Self() = 0 THEN
        RETURN FALSE
    END IF
    VAR current = UO.Weight()
    VAR maximum = UO.MaxWeight()
    IF maximum <= 0 THEN
        RETURN FALSE
    END IF
    RETURN extra <= maximum - current
END SUB
```

**Пояснення параметрів і виконання:**

- CanCarry(extra) отримує додаткову вагу у stones; 10 — приклад, не число стосів. Відхиляє від’ємний extra, відсутній Player або maximum <= 0, читає вагу й межу та повертає Integer Boolean: 1=TRUE чи 0=FALSE за extra <= maximum - current. Віднімання уникає переповнення current + extra. Перевантаження дає false навіть для extra=0. Це локальна оцінка, не дозвіл сервера; читання не атомарні, нульова вага може бути невідомою.
