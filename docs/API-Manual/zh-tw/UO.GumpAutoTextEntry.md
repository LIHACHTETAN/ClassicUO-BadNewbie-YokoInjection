# UO.GumpAutoTextEntry

ClassicUO • Runtime API

<!-- yoko-manual: 1 -->
<!-- yoko-locale: zh-tw -->

在第一個符合的伺服器 Gump 控制項設定一次數值；若控制項尚未出現，則保留待執行操作。

## 完整語法

```text
UO.GumpAutoTextEntry(TextEntryID:Any, Value:Any) -> Unit
```

## 參數

- `TextEntryID` — Integer — 對應控制項種類的精確 ID。不是索引、GumpID 或視窗 serial。0 是一般 ID，不會改選第一個控制項。
- `Value` — String — 輸入欄文字；空字串會清空欄位。欄位本身的長度與字元限制仍然有效。

## 傳回值

Unit — 不傳回值：不是成功狀態、新值或伺服器確認。

## 行為

- 先按目前介面順序檢查既有視窗，再檢查收到或重建的伺服器版面。第一個種類與 ID 相符的控制項會消耗這次操作。要指定視窗，請使用帶索引的 NumGump*。
- 待填欄位會在自動按鈕回應之前套用。同一腳本重複指定相同種類及 ID，會替換尚未執行的值。用戶端最多保留 1024 個待填欄位；超過會產生腳本錯誤。
- 程序正常結束後仍保留待執行操作。取消擁有者或以名稱呼叫 Terminate 會移除其操作；TerminateAll 會全部移除，包括已結束程序留下的操作。切換世界也會清空佇列。不會儲存在設定檔。
- 欄位限制可能截短或拒絕文字，但找到控制項仍會消耗這次操作。此命令不傳送按鈕回應，也不等待伺服器。請用 GetGumpInfo/NumGumpTextEntry 檢查文字。

## 範例

### 填入已開啟的控制項

```vb
# 填入已開啟的控制項
#
# 在第一個符合的伺服器 Gump 控制項設定一次數值；若控制項尚未出現，則保留待執行操作。
#
# Unit — 不傳回值：不是成功狀態、新值或伺服器確認。

SUB Main()
    # 33 是範例控制項 ID，請替換成 InfoGump 顯示的實際 ID。第二個參數是設定值。控制項不存在時，操作會等待。

    UO.GumpAutoTextEntry(33, '500')
END SUB
```

**參數與執行說明:**

- 33 是範例控制項 ID，請替換成 InfoGump 顯示的實際 ID。第二個參數是設定值。控制項不存在時，操作會等待。

### 開啟前準備輸入

```vb
# 開啟前準備輸入
#
# 在第一個符合的伺服器 Gump 控制項設定一次數值；若控制項尚未出現，則保留待執行操作。
#
# Unit — 不傳回值：不是成功狀態、新值或伺服器確認。

SUB Main()
    # 33 是控制項 ID，100 是範例確認 ButtonID，0x40001234 是開啟表單物件的 serial。三者都需替換。即使視窗稍後才到達，也會先填入再回應。

    UO.GumpAutoTextEntry(33, '500')
    UO.WaitGump(100)
    UO.UseObject('0x40001234')
END SUB
```

**參數與執行說明:**

- 33 是控制項 ID，100 是範例確認 ButtonID，0x40001234 是開啟表單物件的 serial。三者都需替換。即使視窗稍後才到達，也會先填入再回應。

### 替換等待中的值

```vb
# 替換等待中的值
#
# 在第一個符合的伺服器 Gump 控制項設定一次數值；若控制項尚未出現，則保留待執行操作。
#
# Unit — 不傳回值：不是成功狀態、新值或伺服器確認。

SUB Main()
    # 兩次呼叫皆使用 ID 33。控制項尚未到達時，最後一個值有效。若已開啟，兩次變更會依呼叫順序立即執行。

    UO.GumpAutoTextEntry(33, '500')
    UO.GumpAutoTextEntry(33, '')
END SUB
```

**參數與執行說明:**

- 兩次呼叫皆使用 ID 33。控制項尚未到達時，最後一個值有效。若已開啟，兩次變更會依呼叫順序立即執行。
